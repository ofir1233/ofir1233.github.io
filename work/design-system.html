Case study · Design system

One set of tokens lets a dense AI product read as one product

Hear is an AI platform for contact centers, with dense screens: call tables, scores, filters and chat side by side. I built the design system that makes them speak one visual language.

For
Whoever builds a screen of Hear. So far, that is me, with Claude Code.
The problem
Dense screens need one set of names for color, surface and state.
What I did
Built the tokens, the shared components and their docs, with Claude Code.
Where it stands
Partly shipped: Hear's live theme and Storybook. In full: Hear Design Lab, my working copy of Hear, built in code.

The problem

One screen mixes figures, tables, charts and chat, and must still read as one

Compliance checks every agent, the people who answer the calls, against the center's rules. Its top strip alone holds headline figures, each measured its own way, and a table header with its own team, count and pass mark. Under it sit a grid of scores, a popover with its own chart and a way into chat. Without shared names for color, surface and state, each part would answer the same questions its own way.

Three layers

Components ask for a role, and the role picks the color

I built the tokens in three layers. A component never names a palette color; it asks for a job, such as body text, and that job has one value behind it.

  1. 1
    PaletteNamed colors, each with a stated use. The new brand palette has nine: Ink for body text, Glass Gray for outlines, Coral for what needs attention, Hear Blue for what is selected, Deep Blue for blue text.
  2. 2
    RolesWhat components ask for: canvas, card, body text, muted text.
  3. 3
    Component setsTokens for one component: the score scale, tag fills paired with their text, a data-grid theme.

34 places

In the product, links and icons took their text color from the main button. In April 2026, moving the product onto the design system's colors turned that button coral, and 34 places would have turned coral with it. I pointed each one at the blue role instead, so the button can change without moving a link.

The finding

The product's link blue fails as text, so I proposed a darker one

The 34 links I kept from turning coral now point at Cobalt, and Cobalt fails as text. Because text and surfaces are named tokens, each pair has one contrast ratio, worked out once. The new brand palette gives text its own darker blue, Deep Blue.

Try the product's blue as text

Switch the color of the label and the link. Ratios on white, the popover's card.

1:17:1

Deep Blue on white: 5.0:1, above the 4.5:1 that text needs. It is the darker text blue I propose, from the new brand palette.

WCAG 2 ratios, computed from the hex values. Text under 24px (19px bold) needs 4.5:1; the link here is 16px. On the product's light paper, #F9F9F7, Cobalt drops to 3.9:1. The new brand's bright Hear Blue, #139FFD, is 2.8:1 on white, so it marks what is selected and never carries text.

Proof it holds

Up close, on other screens, each color does only its job

Three crops from screens drawn in the new brand palette, enlarged. None of these screens sets a color of its own; each asks for a role.

The key decision

Scores run in one blue, so a dense map stays readable

HigherLower

Why: on the Topics map, where each topic is a box sized by its calls, red to green would make the colors compete; one blue, deeper for a lower score, keeps it readable, and coral, green and lilac stay for small marks.

One blue to mark, a darker one to read.
