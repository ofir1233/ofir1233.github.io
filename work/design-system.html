01 · The problem

A dense product needs one vocabulary

I built the system to give every screen in the Lab one set of names for color, surface and state.

Read moreShow less

One Agent evaluation page holds a score chart, category bars, filters, version switches and a team table. Elsewhere in the Lab there are data grids, chat, alerts, a kanban board and settings.

I built the base first: a palette and semantic tokens in one CSS file, an initial set of components and a Storybook with foundations. Then I extended it as the Lab grew.

02 · Structure

Six tiers, from foundations to full pages

I sorted Storybook in Atomic Design order, with a Pages tier on top.

Read moreShow less

Pages are stories too

By July, the Pages tier held 28 stories for nine pages, including Agent evaluation and Alerts, with variants such as Default, With Sidebar and Mobile. The Create report page also exports its page-local pieces as stories, so they're documented even though they live inside the page file.

Shared parts, with their specs written down

  • Button, reworked, used in 21 files. I moved the primary from coral to blue and the secondary from blue to neutral. Its loading state sets aria-busy.
  • PageHeader, new, used in 16 page files. Its spec sits in the code: 12px gutters, 16px radius, 1px border, 56px height.
  • SegmentedTabs, new. It exports its 36px height so sibling controls can match it, and calls itself the “single source of truth for its height/look.”
  • Badge, reworked, used in 13 files, with tinted fills that have their own tokens.
03 · Tokens

Every color has a name and a reason

I built the tokens in three layers so components ask for a role, such as body text, rather than a palette color.

Read moreShow less

The Colors page in Storybook states the rule: “Always prefer semantic tokens (--bg-canvas, --text-primary) in components. Use raw palette tokens (--c100, --b80) only for one-off overrides or design explorations.”

Layer 1

Raw palette

10 color families, each with a name, a ramp of steps and a stated use.

  • Pulse Coral · --c100 #FF7056
  • Charcoal · --d100 #181818
  • Blue Cobalt · --b100 #1779F7
  • Plus Growth Green, Lilac, Deep Teal, Sage, Horizon, Neutral and Paper
→
Layer 2

Semantic roles

What components ask for. The dark theme overrides them by role. Each pair shows light, then dark.

  • --bg-canvas
  • --bg-sidebar
  • --text-secondary
  • --text-muted
  • --color-interactive, B80 in dark
→
Layer 3

Component sets

Tokens scoped to one component.

  • --badge-{color}-bg / -bd / -text / -fill for seven badge colors
  • A data-grid theme mapped onto the semantic variables

How each layer grew

  • Palette: an error red apart from the brand. --red100 #E5484D with an 80 step and a hover, commented “destructive (distinct from brand coral).”
  • Semantic: header edges per theme. --page-header-border is none in light and 1px in dark, with --page-header-shadow and --sidebar-outline beside it.
  • Component: badge fills. --badge-*-fill at 12% in light and 20 to 22% in dark.

After building the Actions board, I aligned all of its colors to the system tokens.

Type, and one written exception

Type is Byrd, in seven weights with italics. The scale runs H1 to H8 for titles and P1 to P14 for body, as --type-h* and --type-p* tokens.

I made one typeface exception. News articles set their body text in an editorial serif, marked in the code as “News body text only (deliberate, scoped DS deviation).”

Charts read the same tokens

I built the News charts to take every color from CSS variables, so they flip with the theme. Their good, medium and poor levels use --g100, --c80 and the error red, --red100. The Alerts chart maps its series to the system's accent hues.

05 · Theme & direction

Tokens switch themes, and logical CSS mirrors the layout

One attribute, data-theme on the root element, moves every semantic token to its dark value by role.

Read moreShow less

The app sets it from a saved preference. Under [data-theme="dark"], surfaces, text, borders, badges and the interactive blue change together.

I first built right to left for the News tab in July. A language hook follows the page's lang, and UI strings sit in a dictionary. Logical CSS properties such as borderInlineStart let the layout flip with the text.

In the Lab today, the language menu switches the shell and this screen to Hebrew, and the whole layout mirrors.

06 · Decisions

Where the system forked

I moved the system's documentation from an in-app inspector to Storybook, and put every overlay on the card surface in the dark theme.

Read moreShow less
Decision 1 · Documentation

Document the system in an in-app inspector, or in Storybook?

  • In-app Design InspectorA drawer with Components, Foundations and Icons tabs, fed by a hand-kept definitions file. I built it, fixed its crashes and documented new components in it.
  • StorybookStories that render the real components, in tiers, with docs pages. I put my stories here and removed the Inspector.

Result: Storybook stayed as the one place the system is documented, next to the components it renders, with no separate definitions file to keep in sync by hand.

Decision 2 · Surfaces

Should overlays get their own dark surface?

  • A separate elevated surfaceKeep --bg-elevated on its own dark value, apart from cards.
  • One surface for every overlaySet --bg-elevated equal to --bg-card in dark, so modals, dropdowns and popovers all sit on it.

Result: one dark surface for every overlay. The token's comment reads “so all modals, dropdowns, and popovers share one color.”
