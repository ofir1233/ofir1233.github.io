  1. 01

    One table for every call

    Hear reads every call a contact center takes, and each one becomes a row in Data. The row starts with what happened: the topic and a one-line summary. If an alert went off, it shows a warning sign. Tabs cut the same table into groups: 148 calls need review, 62 are high priority, 17 have alerts.

  2. 02

    The question fits none of the tabs

    In Northwind, the demo workspace, the last 90 days hold 2,000 calls: 223 pages of nine rows. Tabs help narrow that down, but “long refund calls where the customer was unhappy” isn’t a tab. So the filter lets you ask in plain words.

  3. 03

    Rules read the sentence first

    The sentence goes through rules before any AI. “High priority” and “yesterday” each match a rule, so they become two filters: Priority: High and Call date: yesterday’s date. Each is marked “rule”. Because a rule fired, the AI model is not asked. You can type the sentence in English or Hebrew.

  4. 04

    The model fills the gap, then gets checked

    No rule knows mood, and “over 5 minutes” isn’t their “longer than”. So the AI model gets the sentence, with the table’s columns and values to choose from. It writes three filters. Each one is checked against those columns and values, and anything else is dropped. Every chip shows who wrote it and comes off with one click.

  5. 05

    The table changes once, on Apply

    Building a filter takes several clicks. In June, I tried an earlier design without the Apply button. Every click ran the filter right away, while it was still being built. With Apply, you set the conditions first, and the table changes once, here from 2,000 calls to 86. The shared filter from the Alerts page, which Data now uses, works the same way.

  6. 06

    A call opens beside the table

    Click a row and the call opens in a side panel, so the filtered table stays in view. The panel names the alert that went off. Arrow keys move to the next call without closing it, Esc closes it, and the full call is one click away. From the panel, you can ask the AI about that one call.

Where it stands

Hear’s product already turns a sentence into filters. My redesign of how the sentence is read and checked runs in Hear Design Lab, my working copy of Hear, on demo data. I built it with Claude Code from March to October 2026. Each new version of the page went in as a copy, so the earlier one stayed one click away. Two parts reached the product: Data on the shared action menus (April 2026), and an empty state that tells “nothing uploaded” from “nothing matches” (May 2026).
